# AI Infra Commons：第一版产品设计

定位：面向全球 AI Infra 从业者的开放学习与协作社区。通过“学一个系统 → 做一份作品 → 展示能力 → 发现机会”，减少求职者和招聘团队之间的信息差。

先从 LLM inference / serving 切入，覆盖推理基础、vLLM、SGLang、LMCache；后续由实际贡献者扩展到 CUDA/Triton、分布式训练、编译器、网络与集群平台。不要在启动时承诺覆盖全部 AI Infra。

## 用户各自得到什么

| 人群 | 主要问题 | 第一版解决方式 |
| --- | --- | --- |
| 转方向或入门者 | 不知道学什么，也不知道怎样证明学会了 | 有交付物的学习路线，官方资源与作品模板 |
| 有经验的工程师 | 机会分散、技术要求含糊 | 结构化机会目录，按技术、地区、协作方式搜索 |
| 招聘团队 | 简历关键词难以反映实际工作 | 自愿公开的作品名片，查看代码、实验和贡献说明 |
| 开源参与者 | 缺少同行交流和可完成的起点 | Discussions、共学、实验复盘和文档贡献 |

## 第一版用户流程

学习者打开路线 → 阅读官方资料 → 完成任务并自查 → 在自己的仓库保存作品 → 提交公开名片 Issue → 维护者核实本人同意并收录 → 团队通过本人主动公开的联系入口交流。

团队填写机会 Issue → 维护者核对官方入口、职责、报酬和地区范围 → 编辑公开 JSON 并通过 PR 合并 → Actions 构建网站 → 开发者筛选并前往企业官方入口申请。

维护者核对的是资料与来源，不给雇主或候选人作官方背书。讨论、Issue 与 PR 都公开；保密求职只在企业官方渠道完成。

## 技术结构

```text
GitHub repository
  ├─ Issues       用户主动提交职位、作品与更新请求
  ├─ Discussions  问答、共学、作品交流
  ├─ Pull Requests 维护者审核与内容变更
  └─ content/*.json + web/
             │ 合并到 main
             ▼
       GitHub Actions
       校验数据 → 构建静态文件
             ▼
       GitHub Pages
       双语浏览、搜索、标签筛选、本地学习进度
```

数据由 Git 文件保存，构建时变成公开的 `data.json`。访客不直接请求 GitHub API，因而不需要浏览器 token，也不受每个访客匿名 API 配额影响。提交跳转 GitHub 表单，登录由 GitHub 自己处理，不伪造站内登录。

人工审核是明确的 MVP 取舍：起步时简单、可追溯、容易撤回。后续可以添加“生成待审核 PR”的工具，不能让用户修改 Issue 后绕过审核自动上架。网页搜索全部在本地完成。

## 匹配原则

先做用户可理解的筛选：技术交集、工作方式、地区、语言、时间安排，以及对应作品。选中的多个技术标签按任一交集筛选，交集多的靠前，随后按最近确认日期排序。薪酬、经验和雇佣资格先明确展示，不声称已实现自动精确匹配。

不按学校、年龄、性别、国籍、GitHub star 数或提交频率排序；不把是否有上游合入 PR 当作能力门槛。工作地区和工作许可是岗位约束，应明确展示；远程不自动等于全球雇佣。技术相似不代表适合录用。

## 学习与计算资源

当前实现是四条起步路线和 12 个任务，不是 12 节完整授课课程。提供官方来源、实验要求、交付物与记录模板。课程步骤链接滚动更新的官方文档；实际实验必须固定框架 release/commit、模型 revision 和环境，不能承诺“最新版一键兼容”。

没有 GPU 的人可以完成指标解读、源码笔记、计算脚本和实验设计；运行框架与性能测试需自备适配环境。网站不提供 GPU，也不把 GitHub Actions 当作公共训练或推理资源。学习进度只是浏览器内的自我记录，不冒充认证或就业保证。

## 启动节奏

- 第一轮：把当前骨架放到个人仓库，配置 Pages 和 Discussions，检查公开流程。
- 第二轮：用少量真实职位、自愿作品和一轮共同实验验证需求，先明确谁维护、多久响应。
- 第三轮：根据实际反馈补全课程正文、作品点评、过期提醒、订阅或更细的筛选。
- 有稳定需求后：邀请更多维护者，考虑 Organization；私密消息、私密简历、付费撮合等要重新设计存储和托管。

公益性依靠可持续维护：最初比“AI 推荐算法”更重要的是让资料持续有效、让新人能完成作品、让双方实际收到回应。

## 托管范围

GitHub Pages 是静态托管，公开仓库可用免费方案，但并非无限量资源。官方公布站点大小上限 1 GB、每月带宽软限制 100 GB 等；不要把模型权重、大型数据集或课程视频放进网站。

GitHub 对以促成商业交易为主要目的的网站有限制，免费或非营利意图本身不等于明确许可。本设计以学习社区和公开信息目录为起点，不承诺招聘业务在任何规模下均适用 Pages；若产品重心转向招聘撮合，应向 GitHub 确认或调整托管。
