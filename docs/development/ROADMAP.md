# 聘枢 · AI Infra JobHub 开发计划

版本：2026-11-14。愿景是成为全球 AI Infra 开发者持续学习、展示成长和发现工作的公共基础设施。“全球最大”是长期方向；当前不声称已有规模、就业成果或官方背书。

## 本轮迭代：RSI 共同进阶必修与社区入口

- RSI Infra 按 Recursive Self-Improvement 的工程基础设施定义，加入三条职业路线的共同进阶必修，排在各岗位原核心课后。新课 20 天、20 张图解、40 道题，交互涵盖预算、局部/整体收益和重复检验误报。
- 下载实验提供 20 个可运行日课，保存原始 JSON、成本账本、实际 CPU 计时、血缘、留出对照和回滚证据；经验不一定有帮助，负结果也是交付物。配套第9个项目用于形成个人作品。
- 阅读器、日数统计、深链接、搜索和备份扩展到 10/20 天，旧课程与记录保持兼容。
- 各页面右上角提供 GitHub 图标和 Star 入口，点击只打开仓库。
- 首页改用发起者提供的官方图片式访客分布地图，直接放在正文内，无需 JavaScript 也可显示，点击打开对应的国家 / 地区统计页。已核对图片与统计页均正常返回；移除地球示意、空数字和旧脚本依赖。访问口径以提供方为准，不承诺恢复旧 key 或接入前的数据。

## 已交付：从课程目录走向深入学习

1. **原理知识库 `/knowledge/`**：18 篇双语专题，覆盖推理、性能和平台；每篇提供原理、逐步数值算例、流程图、取舍、误区、自查解析、日课引用和官方资料。数字为明确假设下的教学计算。
2. **故障诊断 `/cases/`**：9 个原创案例、27 条分阶段线索和27个调查步骤。配套标准库 CLI 与合成数据，可在 CPU 运行容量、排队、缓存、计时、梯度缩放、通信、重试、背压和探针分析，保存结果与输入哈希。
3. **练习与复习 `/practice/`**：由现有课程生成 220 题。提交后揭示解析，保留首次与最近结果、尝试次数和手动复习选择。题目改动后通过内容指纹区分旧版记录；支持 JSON 校验预览及确认式合并。
4. **学习搜索 `/search/`**：从 110 个日课、18 篇原理专题、9 个案例和 8 个项目生成全文索引；按内容和课程筛选，跳到具体日课。测验答案与案例最终解析不进入搜索摘要。

首页与每门课提供入口，双语知识手册和包含解析的案例手册支持离线阅读。构建会验证专题与案例的日课引用、完整性和来源，打包诊断实验并自动生成题库与索引。个人笔记、答题记录及求职草稿不进入公开索引。

后续优先级：观察真实学员在哪条解释或命令上卡住；邀请独立复现实验与同行审阅；再针对缺口补更深入的数学、Python/张量基础和 GPU 实测。18 篇专题与9个案例是本轮增量，不等于已覆盖整个 AI Infra 学科。没有用内容数量代替学习效果。

## 已交付：让下一步更具体

三条并行开发线对应三类实际阻力：

1. **入门自查 `/start/`**：按自述基础、设备与目标岗位给出带理由的复习日课，保留普通电脑可完成的首小时任务。有基础的人可直接尝试项目，推荐不转成能力评分。
2. **投递记录 `/applications/`**：手动记录机会、投递阶段、下一步日期与笔记，支持筛选、删除后撤销以及备份恢复。页面提示到期事项，不提供后台通知或代投。
3. **招聘需求 `/hiring/`**：把工程问题、必需/优先技能、作品证据、地区和薪资条件写清楚。三类岗位提示、实时预览和待补项清单帮助发布者核对，再由本人提交 GitHub 职位表单。

首页、求职准备页和人才页提供对应入口。个人内容保存在浏览器，各工具使用独立记录；投递与招聘支持 JSON 备份、校验预览和显式确认合并，不通过 URL 或公开目录传递个人草稿。

下一轮应优先验证实际使用：新手能否按首小时步骤保存第一份成果、招聘者能否写出可执行的作品要求、求职者能否持续整理下一步。当前公开岗位、名片与评审队列仍为空；填充它们需要真实参与者及本人授权，不能靠增加工具替代。自愿反馈进入现有 Issue 流程，先修阻塞，再增加功能。

## 产品判断

用户首先需要三个结果：知道今天学什么、拿出可信的作品、找到会回应的合作机会。功能是否值得做，先看它能否改善其中一个结果。课程数量、注册数和 GitHub stars 不单独代表成功。

产品主线：**10 / 20 天学习手册 → 可复现实验与作品 → 自愿公开的能力证据 → 具体岗位或开源合作 → 同行反馈与下一轮学习**。

课程承担结构化引导与练习，不替代官方参考文档；维护者把版本差异、常见误区和实验方法转化为学习路径。所有“完成”都是自我记录，只有获得了真实复现或点评，作品才可另外展示那份证据。不给学员自动生成能力证书或录用分数。

每天建议按课程标注投入约 90–180 分钟；已有先修知识的人完成实践，没有硬件的人交付可明确辨识的设计、源码分析或 CPU 实验。十天是一轮学习周期，不承诺十天胜任所有生产任务。

## 下一阶段：先证明课程确实能被完成

2026-11-13 增量交付：上线 8 个实战项目、浏览器内作品档案生成器，以及学习阻塞/独立复现反馈表单。课程、项目和档案之间已有入口；原始证据、本人贡献和限制由学习者填写，不自动生成成绩。下一步应验证这些工具是否帮助真实学习者完成作品，详细竞争分析见 [COMPETITIVE_STRATEGY.md](../COMPETITIVE_STRATEGY.md)。

建议周期为接下来 2–4 周，具体节奏由参与人数决定，以下是计划而非已完成成果。

1. 为每门课程招募一名维护者或复现志愿者。先集中验证基础、vLLM、SGLang、Mooncake，记录环境与阻塞步骤。
2. 建立标准复现记录：框架 release/commit、硬件、模型 revision、请求分布、原始输出、失败与修复。把已验证版本与仅核对资料明确区分。
3. 课程修正走 PR；每天的官方资料变动或链接失效先修，再添加新课程。重要的环境差异写入对应日期，而不是堆到聊天群。
4. 每次共学围绕一个成果：例如同一负载下的缓存实验，或一个有精度校验的 kernel。允许负面结果、文档与测试贡献。
5. 使用已上线的学习与项目反馈模板记录阻塞或独立复现，并让学员在公开提交前清理私密数据。涉及个别学员的笔记、简历和求职进度仍由其选择分享。

先看这些可解释的指标：第一天能否开始、哪一天最常阻塞、十天后有多少完整作品、多少作品被第二个人复现。起步阶段可用自愿反馈和公开 Issue 统计，不引入隐蔽追踪脚本。

## 再下一阶段：作品与机会之间的连接

建议在至少完成一轮课程复现后推进，而不是为了增长提前制造虚假需求。

- **作品证据卡**：记录问题、本人贡献、环境、结果、限制与链接。把“自我陈述”“同伴复现”“上游贡献”显示为不同证据，避免合成单一能力分数。
- **岗位技能说明**：将职位技能链接到相关课程与作品要求，例如 vLLM 性能岗位应关注负载设计、测量与源码定位，而不只列关键词。
- **双方可解释的匹配**：先处理地点、雇佣范围、时区、语言、工作方式，再展示技术交集与缺口；工作许可按岗位约束说明，不推断国籍等敏感属性。
- **机会质量**：公司官方入口、职责、报酬范围、可雇佣地区、最近确认时间、过期撤下机制。维护者不以账号存在代替身份核实。
- **回复体验**：与自愿参与的团队约定处理周期，记录公开机会是否仍有效。申请结果只在当事人愿意提供时统计。

这一阶段的关键指标是有效回应、真正发生的技术交流与合作，而不是收到多少简历。邮件接收方需要明确数据用途和处理规则；不把简历当作公开训练数据。

## 技术与维护约束

当前保持 GitHub Pages + Issues + Discussions + PR + Actions。课程源文件是 `content/courses/*.json`，构建生成独立 HTML 与两种语言的 Markdown；首页只加载目录摘要。这样既可低成本分发，也方便未来迁移。

静态托管有流量和体积边界，不存模型权重、大视频或大型数据集。随着产品重心和规模变化，应继续核对 GitHub Pages 适用范围；免费、公益意图并不自动豁免托管政策。无需现在采购服务器，但也不承诺所有未来功能都能永久只依靠公开仓库。

每次发布至少核对：数据完整性、来源链接、深链接、双语切换、学习进度、笔记导出、手机阅读、公开资料撤回流程。课程中的硬件实验由具备相应环境的人实际复现后，才标记具体的验证结果。
